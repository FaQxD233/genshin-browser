# 计划：浮窗三个开关并列（鼠标穿透 / 控制按钮 / 隐藏标题栏）+ 设置面板排版

> 状态：已实施（第 2 版），本机单测与端到端通过，用户 2026-11-14 真机试用通过，随 v0.3.14 发布；实施记录见第 7 节
> 日期：2026-11-14
> 来源：用户 2026-11-14：「控制按钮」不该只在开了鼠标穿透后才能开，应和「鼠标穿透」「隐藏标题栏」三个开关并列；这几项现在的排列和样式不好看。
> 第 2 版（同日，用户审阅第 1 版后）：「穿透 + 隐藏标题栏」时标题栏唤不出来是按设计如此，开着控制按钮也一样，不加「控制按钮优先」也不加感应条；第 1 版的「一行浮窗、三个等宽开关按钮」不好看，不做，改为三行开关并列（沿用现在的开关样式）；标题栏外观看惯了，不改（第 1 版给三个按钮加悬停提示也去掉）。

---

## 0. 现状

- 「鼠标穿透右边出现控制按钮、下面一行隐藏标题栏」是第 2 版（5eaff46）的样子。同日第 3 版（a43567b）把「控制按钮」并进了控制台右上角的触屏模式按钮。现在的代码和 11-14 运行的 `dist/win-x64-self-contained`（11-13 17:08 构建）都是第 3 版。
- 第 3 版：设置面板只有「鼠标穿透」「隐藏标题栏」两行开关；控制按钮只在触屏模式出现，而触屏模式固定穿透、标题栏常驻；触屏模式开着时这两个开关置灰。状态表是 `Utils/TitleBarLayout.For(模式, 隐藏标题栏, 触屏模式)`。
- 问题换了个形式还在：控制按钮仍然只能跟穿透一起用，键鼠浮窗不开穿透时用不了。不穿透时标题栏本来就能点，用不着点击层，没有理由把两者绑在一起。

## 1. 逻辑：三个开关并列

- 新设置 `FloatingTitleBarControls`（控制按钮，默认关）：浮窗标题栏的标题换成倒退 5 秒、播放 / 暂停、快进 5 秒三个按钮。和 `FloatingClickThrough`、`FloatingAutoHideTitleBar` 一样随配置导出 / 导入，恢复默认时关掉。
- 三个开关各管各的，没有谁压过谁。开着穿透时窗口收不到鼠标，隐藏的标题栏唤不出来：按设计如此（用户确认），开着控制按钮也一样。
- 状态表（浮窗、键鼠；浏览模式不变，常驻显示标题）：

  | 穿透 | 控制按钮 | 隐藏标题栏 | 标题栏 | 点击层 |
  | --- | --- | --- | --- | --- |
  | 关 | 关 | 开 | 悬停出现，显示标题（现状） | 无 |
  | 关 | 关 | 关 | 常驻，显示标题（现状） | 无 |
  | 关 | 开 | 开 | 悬停出现，显示三个按钮（新） | 无，直接点 |
  | 关 | 开 | 关 | 常驻，显示三个按钮（新） | 无，直接点 |
  | 开 | 关 | 开 | 隐藏，唤不出来（现状，按设计） | 无 |
  | 开 | 关 | 关 | 常驻，显示标题，和视频一起穿透（现状） | 无 |
  | 开 | 开 | 开 | 隐藏，唤不出来（按设计） | 无 |
  | 开 | 开 | 关 | 常驻，显示三个按钮，整条标题栏可点，视频区穿透（新，同触屏模式的标题栏） | 有 |

- 触屏模式不变：一键开启 = 穿透 + 控制按钮 + 常驻，另带触屏 / 键鼠询问；开着时三个开关置灰，关掉回到它们。
- 状态表改为 `TitleBarLayout.For(模式, 穿透, 控制按钮, 隐藏标题栏, 触屏模式)`：
  - 实际穿透 = 穿透 或 触屏；实际控制按钮 = 控制按钮 或 触屏；实际隐藏 = 隐藏标题栏 且 非触屏
  - 常驻 = 非实际隐藏；换成控制按钮 = 实际控制按钮
  - 点击层 = 实际穿透 且 实际控制按钮 且 常驻
  - 标题栏相关代码已经全部按它的结果走，不另加分支。
- 键鼠浮窗开着穿透 + 控制按钮（常驻）时，点击层能收到手指触摸，会弹「切到触屏模式？」卡片，而主窗在穿透，卡片点不到。改为任何询问卡片显示期间都暂停穿透（现在只有「切回键鼠」卡片这样做），收起后恢复。

## 2. 排版：三行开关并列

- 设置面板「鼠标穿透」「隐藏标题栏」两行中间加一行「控制按钮」，三行同一种开关样式、同一列对齐，顺序：鼠标穿透 / 控制按钮 / 隐藏标题栏。不再有「开了穿透才出现」的子选项。
- 触屏模式开着时三个开关一起置灰，悬停提示说明不生效（同现在）。
- 第 1 版的「一行浮窗、三个等宽开关按钮」不做（用户：不好看）。

- 设置面板改成一行三个开关按钮（用户：不好看）；标题栏外观改动，包括给三个按钮加悬停提示（用户：看惯了）。

## 7. 实施结果（2026-11-14）

- 改动：新设置 `FloatingTitleBarControls`（快照、导出 / 导入、恢复默认）；`TitleBarLayout.For` 改为五个输入（模式、穿透、控制按钮、隐藏标题栏、触屏）；`MainWindow` 新属性、两种询问卡片都暂停穿透；控制台「鼠标穿透」「隐藏标题栏」中间加「控制按钮」一行，触屏模式下三行一起置灰；中英文案、README 同步。标题栏 XAML 只改了注释。
- 单测 168/168（状态表改为 14 例；设置落盘、旧文件默认值、配置导出 / 导入往返补控制按钮），Release + 警告即错误，`dotnet format` 两个工程无改动。
- 端到端 `titlebar` 78/78（全新数据目录 + 假视频页）：在原 66 项上补控制台开 / 关控制按钮（设置、开关、提示）、不穿透常驻时三个按钮且无点击层、浮窗放到屏幕上后光标移到顶部唤出带三个按钮的标题栏并用真鼠标点播放 / 快进 / 倒退 / 暂停、移开 1 秒收回、穿透 + 常驻时经点击层点快进 / 倒退、穿透时手指点点击层弹「切到触屏」卡片期间主窗不穿透（拒绝后恢复穿透）、穿透 + 隐藏标题栏时标题栏收起且无点击层、触屏模式下三个开关置灰、重启保留控制按钮、恢复默认关掉控制按钮。`keymouse` 21/21、`app-command` 20/20 复跑通过。
- 测试里发现的原有行为：窗口移动时 `MainWindow_OnLocationOrSizeChanged` 会按取整后的窗口高重取视频区高度，125% 缩放下标题栏收起时 370 会变成 370.4，反复「收起时移动、显示时移动」会慢慢累积。新测试最初在标题栏收起时把浮窗挪回屏幕外，触发了它；已改成先常驻再挪。实际使用中挪窗口基本都在标题栏显示时，未改代码。
- 离屏截图：设置面板中文 560 宽、英文 420 宽（三行对齐）；触屏模式下三行置灰。
- 真机：用户 2026-11-14 试用，反馈没问题。
