# 计划：任务栏右键菜单（跳转列表）

> 状态：已实现（2026-11-13，见第 6 节），用户同日真机确认没有问题
> 日期：2026-11-12
> 来源：用户 2026-11-12：键鼠浮窗开着鼠标穿透时触屏点不到程序，希望在任务栏右键 GenshinBrowser 图标时能选「切换模式」和一些别的操作（手机串流时长按任务栏图标就是右键）。
> 确认（同日）：菜单四项照第 1 节；保持 `requireAdministrator`，每点一次菜单确认一次 UAC（串流时能确认 UAC），不改启动流程。第 2 节只做第 1、2 步（已有实例时转发命令 / 激活）和主窗执行命令、设置跳转列表；第 2 节的提权改动与 `ChangeWindowMessageFilterEx` 都不做（两个进程都是管理员，同权限发消息不受限）。

---

## 0. 现状与约束

- 任务栏右键菜单里程序自定义的项就是「跳转列表」的任务（WPF `System.Windows.Shell.JumpList` / `JumpTask`）。每一项本质是快捷方式：点一下就用指定参数再启动一次程序，不会把消息直接发给正在运行的窗口。
- 程序清单是 `requireAdministrator`：每启动一次都要 UAC。照直做的话，每点一次菜单（包括播放 / 暂停）都要先确认一次 UAC 才执行。串流时可以确认 UAC（用户现在就是这样打开程序的），只是每次都要多点一下。
- 单实例：`App.OnStartup` 用命名互斥量 `Local\GenshinBrowser_SingleInstance_…`，第二个实例激活已有窗口后退出（现在第二次打开程序也要先过一次 UAC）。
- 「任务栏缩略图按钮」不用起新进程，但要鼠标悬停才出现，触屏用不了，而且 11-04 已经否过。

## 1. 菜单项（静态标题，随界面语言）

1. 切换 浏览 / 浮窗
2. 触屏模式 开 / 关
3. 隐藏 / 显示窗口（同 F7）
4. 播放 / 暂停

标题不随状态变化（「切到浮窗」「切回浏览」这种）：跳转列表由系统保存，程序退出后还会显示，随状态变的标题容易过时。

## 2. 点菜单不弹 UAC：改成普通权限启动、需要时自己提权

- `app.manifest`：`requireAdministrator` → `asInvoker`。
- `App.OnStartup` 最前面，按顺序判断：
  1. 带 `--command <名称>`，且已有实例在运行 → 给已有实例的主窗发一条注册消息（`PostMessage`，命令编号放在 wParam），立即退出，不弹 UAC。
  2. 不带命令，且已有实例在运行 → 激活已有窗口后退出（现在的行为；现在这一步要先过 UAC，改后不用）。
  3. 没有实例在运行，且当前不是管理员 → 用「以管理员身份运行」重新启动自己（弹一次 UAC，和现在一样），当前进程退出。带的命令丢掉，只当成打开程序。UAC 点「否」→ 静默退出（和现在一样不启动）。
  4. 已经是管理员（包括程序自己的「重启」、从管理员命令行启动）→ 走现在的逻辑。
- 判断「已有实例」只查、不建互斥量（`Mutex.TryOpenExisting`；普通权限打不开管理员建的互斥量时会抛「拒绝访问」，同样算已有实例）。否则普通权限进程先占住互斥量，提权后的新实例会误判「已有实例」而直接退出。
- 主窗：注册窗口消息 `GenshinBrowser.Command`，用 `ChangeWindowMessageFilterEx` 只给这一条消息放行低权限来源；收到后按编号执行，不认识的编号忽略。四个命令都调现有方法：`ToggleWindowMode`、`TouchMode` 取反、`ToggleFloatingHidden`、`ToggleVideoPlaybackAsync`。
- 跳转列表：主窗显示后设置四项任务（程序路径 + `--command toggle-mode` 等），切换界面语言时重设。

## 3. 影响与风险

- 每次打开程序仍弹一次 UAC（现在也是）；程序已经在运行时，再点图标或点跳转列表都不再弹。
- 打开程序时多一个短命的普通权限进程（约零点几秒，不显示窗口）。
- 提权重启时，普通权限进程里设的环境变量不会带到管理员进程（只影响测试用的 `GENSHINBROWSER_DATA_DIR`；端到端在测试进程里直接创建主窗，不受影响）。
- 程序没在运行时点跳转列表：打开程序（弹 UAC），这一项命令不执行。
- 原神全屏时任务栏是隐藏的，要用任务栏得让游戏窗口化，或用 UU 发 Win 键调出任务栏。
- 这里只能用普通权限测：命令解析、主窗收到命令后的行为、跳转列表内容、两个普通权限进程之间的转发。「普通权限进程 → 管理员实例」的跨权限发消息、UAC 自提权，要你在真机上确认。

## 4. 测试

- 单测：`--command` 名称解析（四个名称 → 编号；未知名称、缺参数拒绝）。
- 端到端：向主窗发命令消息，四个命令各自生效；跳转列表的标题与参数；第二个进程带 `--command` 启动时把命令转给第一个实例后退出（同为普通权限，测转发链路）。
- 真机：首次打开只弹一次 UAC；程序运行时从任务栏右键（手机上长按图标）点四项，不弹 UAC、都生效；程序已运行时再点任务栏图标不弹 UAC。

## 6. 实现与测试（2026-11-13）

- `Models/AppCommand.cs`：四个命令，数值放在窗口消息的 wParam 里。
- `Services/AppCommands.cs`：菜单项表（命令、命令行名称 `toggle-mode` / `toggle-touch` / `toggle-hide` / `toggle-playback`、文案键）；`TryParse` 从命令行取 `--command 名称`；注册窗口消息 `GenshinBrowser.AppCommand`，`Post` 投给已有实例、`TryRead` 在窗口过程里认消息（编号不认识的忽略）；`CreateJumpList` 生成四个任务（起始目录为程序所在目录，图标用程序图标，不显示「最近」「常用」）。
- `App.OnStartup`：已有实例时按原来的办法找它的主窗（同名进程的 `MainWindowHandle`；F7 隐藏是最小化，仍算可见；控制台和点击层都有 Owner），带命令就投命令，不带就照旧激活。正常启动后在 `ApplicationIdle` 设跳转列表（主窗构造时才定下界面语言），之后切换语言时重设；设置失败只记日志，任务被系统拒绝时记一行调试日志。
- `MainWindow`：`SourceInitialized` 挂消息钩子，收到命令投递到窗口过程外执行，和热键、控制台按钮走同一套方法（`ToggleWindowMode`、`TouchMode`、`ToggleFloatingHidden`、`ToggleVideoPlaybackAsync`）；浏览模式下切触屏模式在控制台提示（浮窗里由 `TouchMode` 自己弹 OSD）；每条命令记一行调试日志 `Jump list command: …`。
- 中英文案 `JumpList.*`，README「窗口模式」加一条。
- 测试：单测 160/160（新增 `AppCommandsTests` 24 项：名称解析、消息编号、跳转列表内容）；`dotnet format --verify-no-changes` 通过；端到端 `app-command` 20/20：子进程跑程序自己的启动流程带 `--command` 把四个命令转给已有实例的主窗，各自生效（浏览模式开触屏有控制台提示、切浮窗、播放 / 暂停、隐藏 / 恢复、浮窗里关触屏、切回浏览），子进程约 0.2 秒退出；不认识的命令名、编号 0 / 99、发给控制台的命令都不执行；隐藏时进程的 `MainWindowHandle` 仍是主窗；跳转列表标题随界面语言切换，交给系统不被拒。
- 真机（这里只能用普通权限测）：管理员身份运行的程序设的跳转列表在任务栏右键出现、点一项 → UAC → 生效，用户 2026-11-13 确认没有问题。
