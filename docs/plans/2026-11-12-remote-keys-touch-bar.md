# 计划：远程按键触发热键 + 穿透时标题栏控制按钮

> 状态：已实施（第 3 版：触屏模式），本机单测与端到端通过，待真机（UU 远程）确认，见第 7 节
> 日期：2026-11-12
> 来源：用户 2026-11-12：手机经 UU 远程串流本机玩原神。用第三方启动器开移动端 UI 后，角色切换按钮被浮窗挡住；想开鼠标穿透配合半透明，但开了穿透，触屏就没法在看攻略时暂停 / 快进 / 倒退。不开移动端 UI 时，UU 远程发来的 K 键本程序也不认。
> 第 2 版（同日）：用户提出把控制按钮放进标题栏：「鼠标穿透」开关右边出现子选项「控制按钮」，开启后标题文字换成三个控制按钮，标题栏不隐藏；同时把「浮窗隐藏标题栏」做成选项，默认隐藏。第 1 版第 2 部分的独立触控条作废。
> 确认（同日）：按第 2 版实施；2.4 按钮大小先不加，实测不够再说；第 5 节第 2、3 条按建议执行。第 2 版已提交（5eaff46）。
> 第 3 版（同日）：用户希望做成「触屏模式」：只在程序实际收到触摸输入时提示（系统报告的触摸屏不准，串流结束后有时还在）；开关不放成「浏览 | 浮窗」旁的第三段，放在控制台右上角作第五个按钮；浮窗模式收到触摸时自动弹窗询问，浏览模式提示一下。「控制按钮」子开关并入触屏模式。见第 7 节。

## 0. 现状与原因

### 0.1 K 键不认

- 键盘钩子主动丢掉所有「注入」的按键：`Services/KeyboardHookService.cs` 的 `HookCallback` 里，`flags` 带 `LLKHF_INJECTED`（0x10）或 `LLKHF_LOWER_IL_INJECTED`（0x02）的事件直接放行、不当热键处理。这是 2026-08-17 全量审查时加的（68dd4de），理由是密码管理器自动输入、输入法合成的按键不该触发热键，注释里也点名了远程控制软件。
- 远程软件（UU 远程、Parsec、Sunshine 等）通常用 `SendInput` 把手机上的按键送到电脑，系统会给这些事件打上注入标志，于是被钩子丢掉。游戏不看这个标志，照常收到（你在 PC 界面下用 UU 键位玩就是这样）。
- 还差一次实测：本机装了 UU 的虚拟 HID 驱动（`E:\Program Files\uuyc\GameViewer\bin\drivers\uuycinput`），设备管理器里有它建的一个虚拟键盘（`HID\HID_DEVICE_SYSTEM_VHF&COL01`）和两个虚拟鼠标。如果 UU 的按键走这个虚拟键盘，事件不带注入标志，就不是上面这个原因，那时更可能是 UU 的方案同时按住了 Alt / Shift 之类，修饰键对不上。第 1 部分顺带加一条日志，实测一次就能分清。

### 0.2 穿透

- 鼠标穿透：`FloatingClickThrough`，`WindowModeService.SetClickThrough` 给整个主窗加 `WS_EX_TRANSPARENT`。
- 主窗是分层窗（`AllowsTransparency=True`），只能整窗穿透或整窗可点：分层窗只有 alpha 为 0 的像素会让点击穿过去，视频画面不行；`WM_NCHITTEST` 返回 `HTTRANSPARENT` 也只对同一线程的窗口有效。
- 标题栏也在主窗里，开穿透后它和视频一起穿透。所以「穿透时标题栏上的按钮能点」需要另开一个窗口盖在标题栏上接收点击（见 2.2）。
- 你现在的浮窗在右上角 (1389.6, 0)，658×371，不透明度 80%；移动端 UI 的角色栏在屏幕右侧，正好被压住。

### 0.3 标题栏现状

- 浏览模式常驻。浮窗模式默认隐藏：鼠标移到窗口顶部 30 像素的感应带时出现，离开 1 秒后收回；穿透时唤不出来。
- 标题栏出现时窗口向下加高 30、视频区高度不变（`SetTitleBarVisible` / `AdjustWindowHeightForTitleBar`，以内容区高度为真源）；settings.json 里存的是视频区高度。

## 1. 第 1 部分：远程 / 模拟按键也能触发热键

- 新设置 `HotkeysAcceptInjectedInput`，默认关（保持现在的行为）。控制台「按键绑定」的「生效范围」下面加一行开关「远程按键」，提示文字：开启后，UU 远程、Parsec 等远程软件和按键映射工具发出的按键也能触发热键；密码管理器自动输入的同名键也会触发。
- `KeyboardHookService` 加 `AcceptInjectedInput`（volatile bool）；`HookCallback` 只在它为 false 时丢弃注入事件。修饰键判断照旧用 `GetAsyncKeyState`（注入的按键同样会更新它），不改。
- 开关关着、注入的按键正好命中某个热键时，每次运行只记一条 DEBUG 日志（VK、flags），用来确认 UU 走的是哪条路；普通打字不记。日志走 `FileLogger` 的异步队列，不拖慢钩子回调。
- 做完以后，不开移动端 UI 时，UU 键位方案里放 K、`;`、`'`（以及 F7、F8）就能控制。

## 2. 第 2 部分：标题栏控制按钮 + 「隐藏标题栏」选项

### 2.1 设置与状态

- 「隐藏标题栏」（浮窗模式，默认开）：开 = 现在的行为；关 = 浮窗标题栏常驻。
- 「控制按钮」：在「鼠标穿透」开关右边，穿透开启时才出现。开启后，浮窗处于穿透时标题栏常驻，标题文字换成「倒退 5 秒 | 播放 / 暂停 | 快进 5 秒」。
- 状态表（浏览模式不变，始终常驻、可点）：

  | 浮窗状态 | 标题栏 | 能不能点 |
  | --- | --- | --- |
  | 不穿透，隐藏标题栏开 | 悬停时出现（现状） | 能 |
  | 不穿透，隐藏标题栏关 | 常驻，显示标题 | 能 |
  | 穿透，控制按钮关，隐藏标题栏开 | 隐藏（现状） | — |
  | 穿透，控制按钮关，隐藏标题栏关 | 常驻，显示标题 | 不能，和视频一起穿透 |
  | 穿透，控制按钮开 | 常驻，标题换成三个按钮 | 整条标题栏能点（三个按钮、模式、铺满、最小化、最大化、关闭、拖动），视频区照旧穿透 |

- 这张表写成一个纯函数（输入：模式、隐藏标题栏、穿透、控制按钮；输出：是否常驻、是否显示控制按钮、是否需要点击层），单测覆盖整张表；标题栏相关代码都按它的结果走。

### 2.2 穿透时让标题栏能点：点击层

- 新窗口 `Windows/TitleBarClickLayer.cs`（纯代码）：无边框分层窗，背景 Alpha=1（肉眼看不见，但能接收点击；主窗背景也是 Alpha=1）；`Owner` 为主窗；加 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，不加 `WS_EX_TRANSPARENT`。
- 按物理像素对齐到主窗标题栏（主窗外框位置 + 标题栏高度 × DPI），主窗移动、改尺寸、换 DPI、标题栏高度变化时跟着更新；只在状态表最后一行显示，主窗最小化（含 F7 隐藏）时系统会把它一起藏起来。
- 按钮仍然只在主窗标题栏里放一份：点击层收到点按后，换算到主窗标题栏上的同一位置找按钮，找到就触发那个按钮（走按钮自己的点击逻辑）；没找到就当作拖标题栏，手动移动主窗（不用 `DragMove`：可能激活窗口，触摸下也不可靠），松手后照旧保存位置；双击照旧最大化 / 还原（和现有拖动栏共用同一段处理）。
- 点击层不激活，点完游戏不丢焦点。例外：点「切到浏览」会显示控制台（本来就会激活）；点「视频铺满」时，WebView2 运行时 157 起要求页面有焦点，游戏在前台时可能被拒，OSD 会提示铺满被拦截，实测后再定。
- 代价：经点击层操作时，按钮没有悬停高亮和提示文字，结果看浮窗底部 OSD。

### 2.3 标题栏里的三个按钮

- `MainWindow.xaml` 标题那一列加三个按钮（`TitleBarButton` 样式，字形沿用 OSD：倒退 EB9E、播放 E768 / 暂停 E769、快进 EB9D），默认折叠；进入状态表最后一行时显示按钮、折叠标题文字，离开时换回来。
- 点击直接调 `SeekVideoAsync(-5)`、`ToggleVideoPlaybackAsync()`、`SeekVideoAsync(5)`，结果照旧在 OSD 显示；播放 / 暂停按钮的图标按上一次操作的结果切换；提示文字带上对应热键。

### 2.4 按钮大小（先不做）

- 标题栏只有 30 逻辑像素高。你的屏幕逻辑宽约 2048，16:9 画面铺在手机上约 12 cm 宽，30 只有约 1.8 mm 高，手指不容易点准；点偏到下面的视频区会穿透给游戏。
- 用户 11-12 决定先不加，实测不够再说。到时的做法：给控制按钮状态加三档标题栏高度（如 30 / 44 / 60），把常量 `TitleBarExpandedHeight` 相关的约 7 处计算改成「当前标题栏高度」，高度变化时视频区高度不变。

### 2.5 设置界面与接线

- 控制台「窗口」区：「鼠标穿透」开关右边出现「控制按钮」开关（穿透开启时才显示）；新增一行「隐藏标题栏」开关（默认开）。
- 设置字段：`FloatingAutoHideTitleBar`（默认 true）、`FloatingClickThroughControls`（默认 false）。接入快照、导入（`ApplyImportedSettings`）、恢复默认（都回默认值）、`IControlBrowser`、控制台 VM 与 XAML、中英文案、README。
- 标题栏逻辑的改动点：`RestoreWindowBounds`（启动时按状态表决定是否常驻）、`ApplyTitleBarForCurrentMode`、自动收回计时、`FloatingClickThrough` 与新设置的 setter 里重新应用。

## 7. 第 3 版：触屏模式（2026-11-12）

### 7.1 设计

- 新设置 `TouchMode`（默认关，替代第 2 版的 `FloatingClickThroughControls`）：开启后浮窗固定为穿透、标题栏常驻并换成三个控制按钮（点击层照旧）。键鼠用的「鼠标穿透」「隐藏标题栏」不受影响，关掉触屏模式就回到它们，所以不用另存一份。触屏模式属于本机运行状态：重启保留，但不随配置导出、导入；恢复默认时关掉。
- 状态表简化为 `TitleBarLayout.For(模式, 隐藏标题栏, 触屏模式)`：浏览常驻；浮窗触屏 → 常驻 + 控制按钮 + 点击层；浮窗键鼠 → 常驻与否只看「隐藏标题栏」。浮窗是否穿透 = 鼠标穿透 或 触屏模式（`MainWindow.EffectiveClickThrough`，统一走 `ApplyWindowMode`）。
- 开关：控制台右上角第五个按钮（设置、按键绑定旁，按下态 = 开）。触屏模式开着时，设置里的鼠标穿透、隐藏标题栏置灰，提示文字说明不生效。多了这个按钮，控制窗最小宽度 400 → 420（最窄时英文「Browsing | Floating」不贴到按钮）。
- 提示：只看程序窗口实际收到的手指触摸（`TouchInputWatcher`，主窗与控制窗各挂一个）。浮窗模式在主窗中间弹询问卡片「切到触屏 / 继续用键鼠」（按钮 40 高，12 秒没回应按继续用键鼠处理）；浏览模式在控制台提示 6 秒。每次运行各一次。键鼠浮窗开着鼠标穿透时收不到触摸，不提示。

### 7.2 实测发现（InjectTouchInput 注入真实触摸，分层窗口）

- 进程里的第一次触摸：窗口过程收到 `WM_POINTERDOWN`（类型为手指）和系统转出来的鼠标消息（附加信息 `0xFF5157xx`），WPF 不产生任何触摸、手写笔、鼠标事件，按钮不响应。
- 之后 WPF 的触摸栈接手：窗口过程不再收到 `WM_POINTERDOWN`，只剩转出来的鼠标消息，WPF 正常产生事件。
- 所以检测同时认两种：`WM_POINTERDOWN`（手指）或带触摸标记的鼠标按下（`Services/PointerMessages`）。
- 点击层：`WS_EX_NOACTIVATE` 挡不住触摸带来的激活，第一下点击层就成了前台，游戏丢焦点。现在窗口过程里对 `WM_POINTERACTIVATE` / `WM_MOUSEACTIVATE` 都回答不激活；触摸 / 笔用转出来的鼠标消息自己处理（按下、移动、抬起，`SetCapture` 接住拖动），WPF 那边由触摸产生的鼠标事件忽略，免得同一下处理两次。
- 消息钩子要按句柄取 `HwndSource.FromHwnd`：在 `OnSourceInitialized` 里 `PresentationSource.FromVisual` 取不到，点击层的钩子曾因此没挂上。
