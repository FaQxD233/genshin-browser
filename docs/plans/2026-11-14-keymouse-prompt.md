# 计划：触屏模式下收到键鼠操作时，询问要不要切回键鼠模式

> 状态：已实现（同日，见第 6 节），待真机确认
> 日期：2026-11-14
> 确认（同日）：第 1 节选 a + b（不做 c）；第 2 节浮窗中间卡片 + 询问期间暂停穿透；第 3 节每次切换模式后重新问（触屏提示也照此改）。
> 来源：用户 2026-11-14「如果接收到键鼠操作，应该弹出要不要换成键鼠模式」。是触屏提示（收到手指触摸时问要不要切到触屏模式）的反方向。

---

## 0. 现状与约束

- 触屏提示：主窗、控制台收到手指触摸时，浮窗弹询问卡片（键鼠浮窗没开鼠标穿透时才收得到触摸），浏览模式在控制台提示；每次运行各一次，拒绝或 12 秒没回应就不再问。
- 触屏模式的浮窗整窗鼠标穿透，只有标题栏经点击层可点。鼠标点在视频区直接落到游戏，程序收不到；浮窗里弹出的卡片鼠标也点不到。
- 浮窗模式的主窗没有「不激活」样式：不穿透时用鼠标点它，会把焦点从游戏抢过来。
- 全局键盘钩子已经装着（热键用），每个按键都会经过回调，能分出注入的键（远程软件、按键映射工具用 SendInput 发的）。没有全局鼠标钩子。
- UU 远程发来的键是不是注入的，还没确认：UU 在本机装了虚拟键盘 / 鼠标（VHF）。如果它走虚拟键盘，在程序看来就和实体键盘一样。真实日志里 11-12 以后没有「忽略注入按键」的记录，无法判断。

## 1. 什么算「键鼠操作」（只在触屏模式开着时看）

- a. **实体键盘按键**，不管哪个窗口在前台：在现有键盘钩子里多看一眼，不是注入的按下就算。坐回电脑一打游戏（WASD）就能发现。【建议】
- b. **鼠标点本程序的窗口**（触屏浮窗的标题栏、控制台、浏览模式的主窗）：按下、滚轮都算，由触摸转出来的鼠标消息不算。【建议】
- c. 鼠标在任何地方移动（原始输入 WM_INPUT，不拖慢游戏里的鼠标）：坐回电脑只动鼠标、不按键也能发现。代价是触屏模式开着时，每次鼠标移动都要收一条消息。【不建议先做】
- 风险：如果 UU 发的键不是注入的，在手机上用 UU 按键也会被当成实体键盘，触发误报。真机上出现这种情况时，再按设备排除 UU 的虚拟键盘。

## 2. 怎么问

- **触屏浮窗**：浮窗中间弹卡片，和触屏询问卡片同样式：
  - 标题「检测到键鼠操作」，正文「切回键鼠模式？浮窗会按设置里的鼠标穿透、隐藏标题栏。」，按钮「继续用触屏」「切回键鼠」。
  - 卡片显示期间，浮窗暂停穿透，鼠标才点得到卡片；点卡片不激活窗口，游戏不丢焦点。
  - 回答或 12 秒没回应后恢复穿透。这期间点视频区会点到网页，而不是游戏。
  - 备选：问句放进标题栏。标题栏本来就能点，不用暂停穿透，但地方小，窄窗口和英文会挤。
- **浏览模式**：控制台提示一次，和触屏提示对称：「检测到键鼠操作。触屏模式还开着：进浮窗后仍会穿透，标题栏显示控制按钮。要改回键鼠，点右上角的触屏按钮。」

## 3. 多久问一次

- 现在的触屏提示每次运行各问一次。程序随游戏常驻几周，等于只问一次。
- 建议改成：每次在触屏和键鼠之间切换后，两边的提示各重新问一次；拒绝或超时后，到下次切换前不再问。这样：
  - 手机上用完回到电脑，会问一次要不要切回键鼠；
  - 切回后下次再用手机，又会问一次要不要切到触屏。
- 这条也改变现有的触屏提示。

## 4. 改动（确认后细化）

- `KeyboardHookService`：触屏模式开着时，第一个实体（非注入）按键按下发一次事件，之后等重新开启。钩子回调里只改标记，界面改动投递出去。
- 输入观察：`TouchInputWatcher` 扩成同时认出「手指触摸」和「实体鼠标按下 / 滚轮」；点击层的鼠标（非触摸）按下也报给主窗。
- 主窗：
  - 询问卡片改成通用的，有触屏、键鼠两套文案；
  - 键鼠询问期间暂停穿透，并对 `WM_MOUSEACTIVATE` 回答不激活；
  - 按第 3 节的规则重新开启两种提示。
- 中英文案、README、计划文件。
- 测试：
  - 单测：钩子回调分辨注入 / 实体按键。
  - 端到端：反射调用钩子回调模拟实体按键（SendInput 发的键都带注入标记，测不了实体键）；SendInput 鼠标点标题栏；卡片点按后恢复穿透、游戏不丢焦点；重新问的规则。

## 6. 实现与测试（2026-11-14）

- `KeyboardHookService`：`WatchPhysicalKeys` 打开时，下一次不带注入标记的按下（含 Alt 等系统键）发一次 `PhysicalKeyPressed`，随即自己关掉；钩子回调里只改标记。
- `PointerInputWatcher`（由 `TouchInputWatcher` 改名）：手指照旧（WM_POINTERDOWN 手指、由触摸转出的鼠标按下）；鼠标是左 / 右 / 中 / X 键按下、非客户区左键、滚轮，且不是由触摸 / 笔转出的。挂在主窗、控制台、标题栏点击层上。钩子由 HwndSource 强引用（查过 WPF 源码），不再另存一份列表。
- 主窗：
  - 询问卡片改成通用的 `ModePromptCard`，触屏 / 键鼠两套文案按资源引用挂上，界面语言切换时跟着变。
  - 键鼠询问期间暂停穿透（`EffectiveClickThrough` 把它算进去），收起（回答、超时、模式或穿透变了）时恢复。
  - 两种询问显示期间，主窗都带 `WS_EX_NOACTIVATE`，并对 `WM_MOUSEACTIVATE` / `WM_POINTERACTIVATE` 回答不激活；卡片按钮不可聚焦。
  - 实测：只回答 `WM_MOUSEACTIVATE` 不激活时，鼠标点卡片后前台变成「没有前台窗口」，原来的前台程序还是丢了焦点；加上 `WS_EX_NOACTIVATE` 后，前台保持不变。
  - `TouchMode` 每次切换都把四个「问过了」标记清掉，并按当前模式重新打开实体按键监听。F7 隐藏（最小化）时实体按键先不问，留到恢复后的下一次。
- 中英文案 `KeyMousePrompt.*`、`KeyMouseHint.Browse`，README 同步。
- 测试：
  - 单测 161/161，新增钩子回调测试：注入、抬起不算，第一下实体按下报一次后关掉，Alt 也算。
  - 端到端新增 `keymouse` 模式 21/21：
    - 测试先卸掉真的键盘钩子，实体按键改为直接调钩子回调（SendInput 发的键都带注入标记），鼠标用 SendInput。
    - 覆盖：浏览模式提示；注入的键不算；浮窗卡片暂停穿透；鼠标点卡片后前台不变；拒绝后不再问；切换后重新问；用鼠标点标题栏触发；「切回键鼠」；触屏询问的重新问；超时恢复穿透；隐藏时不问。
  - `titlebar` 66/66、`app-command` 20/20 复跑通过。
- 要真机确认：
  - 用 UU 在手机上按键时，会不会被当成实体键盘（误报询问）；
  - 坐回电脑按键、点浮窗标题栏时问得及时；
  - 点卡片后游戏不丢焦点。
